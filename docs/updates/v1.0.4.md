# Money Tracker 1.0.4 (build 5)

## Included

- Retains the established interface. The experimental pocket-first redesign was reverted before this update.
- Adds the expense category `Tempat Tinggal` immediately after `Layanan`, without renaming existing categories or transactions.
- Adds monthly category budgets with in-app warnings at 80% and 100%.
- Adds history date/category filters, period comparisons, and CSV sharing for the selected report period, pocket and transaction type.
- Validates backups before restoring, restores transactionally, and continues accepting older backup files.
- Protects transfers when deleting pockets and keeps transaction/pocket state synchronized.
- Adds persistent PIN retry protection and a personal PIN setup flow for installations without a saved PIN.
- Discloses the data shared with Gemini, handles unavailable financial data and AI errors, and guards repeated save submissions.
- Uses the Android device time zone for reminders and reports permission/scheduling failures.
- Includes targeted privacy, contrast and large-text fixes without replacing the established visual design.
- Updates the Android build configuration to Kotlin 1.8.22 and Android Gradle Plugin 7.4.2.

## Upgrade compatibility

SQLite version 2 adds only the `category_budgets` table. Existing financial records and secure-storage keys are retained. Upgrade regression tests cover version-1 data and older backups.

Android updates require the same application ID and signing key as the installed app. The current project still uses its existing debug signing configuration for release builds. Back up before updating and do not uninstall to work around a signing mismatch.

## Verification

- `flutter test`: 75 passed; 12 opt-in screenshot tests skipped in the default run.
- `flutter analyze`: no issues found.
- The restored-interface release APK was built successfully as version `1.0.4`, version code `5`.
- Native sharing, file picking, biometrics, notification delivery and in-place upgrade behavior still require device verification; automated tests do not replace these checks.

Build outputs, local agent configuration, user databases and credentials are not included in the source update.
